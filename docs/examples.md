# Examples

These fictional submissions use the same questions and rule inventory. Each JSON file and its CSV counterpart contain the same answers, dated **December 7, 2026**. Each rule uses no more than five short sentences across its narrative fields; this is an example-writing limit, not a submission constraint.

| Offering | Approach | Download |
| --- | --- | --- |
| **Aster Operations Cloud** — 20x Class C | Addresses every applicable rule with automated monitoring, integrated GRC records, and SOC decisions supported by AI checks. Its operating targets generally exceed required or recommended intervals. | [JSON](downloads/automated.json) · [CSV](downloads/automated.csv) |
| **Harbor Agency Workspace** — Rev5 Class C | Addresses all applicable MUST and MUST NOT requirements. Legacy tools and manual handoffs leave most SHOULD recommendations incomplete; segmentation and review procedures reduce some resulting risks. | [JSON](downloads/legacy.json) · [CSV](downloads/legacy.csv) |
| **Smallbrook Public Information Workspace** — Rev5 Class B | A small provider with incomplete MUST and SHOULD implementation, weekly manual evaluations, and a focus on availability. It limits use to noncritical public information and acknowledges that these limits do not remove the gaps. | [JSON](downloads/availability.json) · [CSV](downloads/availability.csv) |

[Load an example in the validator](validate.md). The files include specific implementation descriptions, completion targets or explained exceptions, and practical risk-compensation answers. Optional assurance appears mainly in Aster’s responses.

A passing file can contain **Not Addressed** rules. Passing means the file meets this collection’s format and completeness checks; it does not establish compliance or endorse the provider’s risk decisions.
